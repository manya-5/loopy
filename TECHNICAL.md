# Technical Architecture & Implementation Overview: Loopy

This document provides a comprehensive technical overview of **Loopy**, a personalized tech news briefing application. Every description and instruction in this document directly reflects the actual code and configuration implemented in this repository.

---

## 1. System Architecture & End-to-End Flow

Loopy connects an interactive vintage broadsheet web frontend to an ADK agent deployed on Google Cloud Vertex AI Agent Platform (Agent Runtime) using the Agent-to-Agent (A2A) protocol, Firestore, and Vertex AI Memory Bank.

```
┌────────────────────────────────────────────────────────┐
│               Browser (Newspaper UI)                   │
│         /static/index.html + /aged_paper_texture.png   │
└───────────────────────▲────────────────────────────────┘
                        │ HTTP POST /chat {"message", "user_id"}
                        ▼
┌────────────────────────────────────────────────────────┐
│            FastAPI Proxy Server (frontend/main.py)     │
│   - Same-origin static file serving                    │
│   - ADC Bearer token authentication & per-user session │
│   - A2A ClientFactory over HTTP passthrough            │
└───────────────────────▲────────────────────────────────┘
                        │ A2A Protocol (JSON-RPC over HTTPS)
                        ▼
┌────────────────────────────────────────────────────────┐
│  Vertex AI Agent Runtime (agents-cli 1.4.0 / ADK 1.1)  │
│  Endpoint: reasoningEngines/4438471155610812416       │
│  Model: gemini-3.6-flash                               │
├────────────────────────────────────────────────────────┤
│  Callbacks & Tools:                                    │
│   - PreloadMemoryTool (Vertex AI Memory Bank)          │
│   - generate_memories_callback (after_agent)           │
│   - a2ui_callback (after_model A2UI v0.8 parser)       │
│   - fetch_sources & fetch_recent_articles               │
└──────────────┬─────────────────────────┬───────────────┘
               │                         │
               ▼                         ▼
┌─────────────────────────────┐  ┌───────────────────────┐
│     Cloud Firestore         │  │ External News Feeds   │
│ Collection: "sources"       │  │ - HN Algolia API      │
│ (17 curated sources)        │  │ - 16 RSS / Atom Feeds │
└─────────────────────────────┘  └───────────────────────┘
```

### End-to-End Execution Trace: Selecting a Role

When a user clicks a role chip (e.g., `Design Engineer`) or types a custom job description:

1. **User Action & Masthead Update (`index.html`)**:
   - The browser updates the masthead dynamically (e.g., `"The Design Engineer Times"`, `EDITION: DESIGN ENGINEER`).
   - The typewriter loading line starts cycling through monospace newsroom phrases (`"SETTING TYPE..."`, `"PULLING WIRES..."`, etc.).
   - The browser sends an HTTP `POST` to `/chat` with JSON body `{"message": "I'm a Design Engineer", "user_id": "newspaper_reader"}`.
2. **FastAPI Proxy Request Handling (`frontend/main.py`)**:
   - The proxy refreshes Google Cloud Application Default Credentials (ADC) to obtain a Bearer token with Cloud Platform scope.
   - It fetches the agent card from the Agent Engine passthrough URL: `https://{LOCATION}-aiplatform.googleapis.com/reasoningEngines/v1/{RESOURCE}/api/a2a/{AGENT_DIRECTORY}/.well-known/agent-card.json`.
   - Using `a2a-sdk`'s `ClientFactory`, it sends an A2A `Message` containing the user prompt and context ID.
3. **Agent Invocation & Memory Preloading (`app/agent.py`)**:
   - The deployed `root_agent` receives the message.
   - `PreloadMemoryTool` retrieves any cross-session memories persisted for the user.
4. **Tool Execution (`app/firestore_sources.py` & `app/article_fetcher.py`)**:
   - The model invokes `fetch_recent_articles(role="Design Engineer")`.
   - `get_sources_for_role` queries Firestore's `sources` collection:
     - For standard roles, it runs `collection.where("roles", "array_contains", "Design Engineer")`.
     - For custom descriptions, it scores documents based on matched keywords (`design`, `frontend`, `backend`, `pm`).
   - For each matching source, `fetch_recent_articles_for_role` queries:
     - **Hacker News**: Algolia search API for stories with $\ge 100$ points created within the last 30 days.
     - **RSS/Atom Feeds**: Parses XML feeds for `<item>` or Atom `<entry>` elements, filtering by a strict 30-day cutoff date.
   - Returning articles are standardized into dictionaries with `title`, `source`, `category` (`news` or `reads`), `published_date` (`YYYY-MM-DD`), and `link`.
5. **Model Synthesis & A2UI Formatting (`app/agent.py`)**:
   - `gemini-3.6-flash` receives the grounded article list.
   - Following system instructions generated by `A2uiSchemaManager(version="0.8")`, it selects up to 5 items (prioritizing news releases, allowing at most 2 reads).
   - It outputs an A2UI JSON array describing a root `Column`, section headers, and article `Card` components containing headline, source, date, role-specific "why it matters", and link.
6. **Callbacks & Memory Extraction**:
   - `after_model_callback` (`a2ui_utils.a2ui_callback`): Inspects the model's text output, extracts and validates the A2UI v0.8 structure, verifies root/child component references, and wraps the payload into `<a2a_datapart_json>` format with metadata `{"mimeType": "application/json+a2ui"}`.
   - `after_agent_callback` (`generate_memories_callback`): Calls `callback_context.add_session_to_memory()` to store the user's role and preferences asynchronously in Vertex AI Memory Bank.
7. **Frontend Extraction & Broadsheet Rendering (`frontend/main.py` & `index.html`)**:
   - The proxy extracts the A2UI data parts and returns `{"parts": [{"kind": "a2ui", "data": ...}]}` to the browser.
   - `index.html` parses the component tree into internal story structures.
   - The loading bar stops, the deck stage appears, and the first story sheet is displayed with an instant ink fade transition and a rotated rubber stamp.

## 2. The Agent Specification

### Model & Configuration
- **Model**: `gemini-3.6-flash` configured via Google ADK (`google.adk.models.Gemini`).
- **Retry Options**: `types.HttpRetryOptions(attempts=3)`.
- **Schema Manager**: `A2uiSchemaManager` pinned to version `0.8` with `BasicCatalog.get_config("0.8")`.

### Core System Instructions
The system prompt enforces five operational rules:
1. **Memory & Role Recall**: Check preloaded memories for prior roles or work descriptions. If returning without stating a role (e.g. *"Give me my briefing"*), personalize using recalled role.
2. **Immediate Tool Execution**: Immediately call `fetch_recent_articles` upon receiving or recalling a role.
3. **Selection & Mix Rules**:
   - Select up to 5 items total.
   - **Lead with news**: Prioritize industry news, product launches, releases, and new tools (`category: "news"`).
   - **AI releases are universal**: Major AI model/tool releases (Gemini, OpenAI, Claude, design tools) are treated as relevant across all disciplines.
   - **At most 2 reads**: Limit longform essays/opinions (`category: "reads"`) to a maximum of 2.
   - Rank by role relevance and publication recency.
4. **Strict Grounding**: Only include real articles returned by `fetch_recent_articles`. Never invent, synthesize, or hallucinate URLs or articles. If fewer than 5 items are found, present only what exists.
5. **Role-Specific Impact**: Tailor the concrete action in *"Why it matters"* to the specific role or typed job description, suggesting concrete tools or workflows.

### Agent Tools
1. **`PreloadMemoryTool()`**: Native ADK tool that queries Vertex AI Memory Bank for cross-session memories tied to the user before model invocation.
2. **`fetch_recent_articles(role: str)`**: Fetches real articles from Firestore-configured sources (HN Algolia search + RSS feeds) published within the last 30 days.
3. **`fetch_sources(role: str)`**: Retrieves metadata for news sources stored in Firestore relevant to a role or work description.

## 4. Fetching, Parsing & Grounding Logic

### Hacker News (`_fetch_hn_articles`)
- **API**: Algolia search API endpoint (`https://hn.algolia.com/api/v1/search`).
- **Filters**: `tags=story`, `points>=100`, and `created_at_i > [now - 30 days]`.
- **Fallback URL**: If an article hit lacks a direct external URL, it falls back to `https://news.ycombinator.com/item?id={objectID}`.

### RSS & Atom Parsing (`_fetch_rss_articles`)
- Fetches XML via `urllib.request` with User-Agent `Mozilla/5.0 (compatible; Loopy/1.0)` and an 8-second timeout.
- Parses XML using `xml.etree.ElementTree`.
- Supports standard RSS `<item>` and Atom `<entry>` elements (`{http://www.w3.org/2005/Atom}`).
- Normalizes publication timestamps (`pubDate`, `published`, `updated`) into UTC `datetime` objects and drops any entry older than 30 days.

### Grounding & Error Tolerance
- Sources that fail network connection, timeout, or return non-200 responses are caught via exception handlers and skipped without crashing the agent.
- Grounding constraint: Only articles retrieved by tool execution can be included in the briefing.

## 5. Memory System

- **Storage Engine**: Google Cloud Vertex AI Memory Bank (`agentengine://7948756035529867264`).
- **Preloading (`PreloadMemoryTool`)**: Executed as a tool by `root_agent` at the start of a conversation to pull prior memories into context.
- **Persistence (`generate_memories_callback`)**: Registered as an `after_agent_callback`. After each turn completes, it executes `await callback_context.add_session_to_memory()` to analyze the session, extract user preferences, roles, or stated tasks, and commit them to the Memory Bank.

## 6. A2UI Surface & Card Structure

The agent emits an A2UI 0.8 specification adhering to the Basic Catalog:
- **Root Element**: `Column` holding section headings and article cards.
- **Section Headers**: `Text` components with `usageHint: "h2"` distinguishing `"News"` from `"Reads"`.
- **Article Card Structure**:
  - `Card`:
    - `Column`:
      1. **Headline**: `Text` component (`usageHint: "h3"`).
      2. **Metadata Row**: `Row` containing two `Text` items: publication name and `YYYY-MM-DD` date.
      3. **Why it matters**: `Text` italicized explanation connecting the news to the user's role.
      4. **Link**: `Text` markdown link (`[Read article](URL)`).
- **Callback Defense (`a2ui_utils.py`)**: Sanitizes un-fetchable images, strips markdown code blocks, unwraps nested JSON envelopes, and validates that all component IDs in `explicitList` and `child` exist. If malformed JSON is generated by the LLM, it falls back to a clean text explanation rather than rendering a blank card.

## 7. Frontend Newspaper Design & Mechanics

The frontend (`frontend/static/index.html`) is a standalone single-page broadsheet newspaper interface:

1. **Aged Paper Background & Texture**:
   - Base color: Warm clean cream (`--bg-paper: #faf6ec`).
   - Texture: Rendered via a fixed viewport overlay (`.paper-texture-layer`) hosting `/aged_paper_texture.png`. It uses `mix-blend-mode: multiply`, `opacity: 0.18`, and CSS filter `grayscale(0.55) brightness(1.22) contrast(1.04)` to provide an organic, non-yellow fibrous paper grain that remains fixed during scrolling.
2. **Masthead & 3-Column Equal Dateline**:
   - Masthead: Typography in **Playfair Display Black** (900 weight).
   - Dynamic Newspaper Name: Generates custom broadsheet titles based on role (e.g., *"The Design Engineer Times"*, *"The Systems & Backend Tribune"*).
   - Dateline Grid: Implemented with strict CSS grid `grid-template-columns: 1fr 1fr 1fr;`. Left column: `EST. 2026`; Center column: formatted newspaper date (`WED., SEPT. 30, 2026`); Right column: `EDITION: [ROLE]`.
3. **Typewriter Loading Line**:
   - Replaces spinners with an inking animation using **Special Elite** monospace font with `white-space: pre` and a blinking rectangular cursor block.
4. **Deck Stage & Smooth Page Flip**:
   - Single-story reader with navigation (`Story 1 of 5`, `Previous`, `Next`).
   - Page Flip: Uses CSS hardware-accelerated transforms (`transform: translate3d(-115%, -18px, 0) rotate(-4deg); opacity: 0;` over 450ms with `cubic-bezier(0.16, 1, 0.3, 1)` and `will-change: transform, opacity`). Filters and shadows are omitted from the moving sheet to maintain 60fps performance.
5. **Ink Stamp**:
   - A faded red (`#b3261e`) rubber ink stamp positioned at the top-right corner with double borders and a slam animation (`stampSlam`):
     - `"HOT OFF THE PRESS"` for stories published today.
     - `"WORTH A READ"` for longform reads.
     - `"EXTRA!"` for breaking news.

## 8. Redeployment Guide (Own Google Cloud Project)

To deploy this project from scratch on your own GCP project:

### Step 1: Enable Google Cloud APIs
```bash
export PROJECT_ID="your-gcp-project-id"
export REGION="us-east1"

gcloud config set project $PROJECT_ID

gcloud services enable \
  aiplatform.googleapis.com \
  firestore.googleapis.com \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  cloudbuild.googleapis.com
```

### Step 2: Create Firestore Database
Create a Firestore database in Native mode:
```bash
gcloud firestore databases create --location=$REGION --type=firestore-native
```

### Step 3: Run the Firestore Seed Script
Update `PROJECT_ID` in `scripts/seed_sources.py` and run:
```bash
uv run python scripts/seed_sources.py
```

### Step 4: Create a Vertex AI Memory Bank (Optional / For Long-Term Memory)
```bash
# Using agents-cli or Vertex AI SDK:
# Retrieve the generated reasoning engine / memory bank URI (e.g. agentengine://<ID>)
```

### Step 5: Grant IAM Permissions to the Runtime Service Account
The Agent Runtime service account requires access to Firestore and Vertex AI:
```bash
PROJECT_NUMBER=$(gcloud projects describe $PROJECT_ID --format='value(projectNumber)')
SERVICE_ACCOUNT="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"

# Firestore User
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/datastore.user"

# Vertex AI User
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/aiplatform.user"
```

### Step 6: Deploy Agent to Agent Runtime
From the project root:
```bash
agents-cli deploy \
  --deployment_target=agent_runtime \
  --region=$REGION
```
Note the deployed resource name output in `deployment_metadata.json` (e.g. `projects/<PROJECT_NUMBER>/locations/<REGION>/reasoningEngines/<ENGINE_ID>`).

### Step 7: Deploy the Frontend to Cloud Run
From the `frontend/` directory:
```bash
cd frontend

gcloud run deploy loopy-frontend \
  --source . \
  --region $REGION \
  --platform managed \
  --allow-unauthenticated \
  --set-env-vars AGENT_ENGINE_RESOURCE_NAME="projects/${PROJECT_NUMBER}/locations/${REGION}/reasoningEngines/${ENGINE_ID}" \
  --set-env-vars AGENT_DIRECTORY="app"
```
